# ISSUE-208 Make castor check safe from active Hatfield sessions

## Goal
GitHub issue: https://github.com/ineersa/agent-core/issues/208

Running `castor check` from inside an active Hatfield session in the same checkout can kill Hatfield's own runtime workers. Current `.castor/tasks.php` ancestry guard protects the Castor launcher/controller ancestors but not sibling workers such as `messenger:consume run_control` and `llm`, so cleanup_stale_check_workers can kill the active session.

Start points: `.castor/tasks.php`, `.castor/process.php`, `src/CodingAgent/Runtime/Controller/ConsumerSupervisor.php`, `src/CodingAgent/Tool/BackgroundProcess/ProcessLifecycle.php`, `AGENTS.md`, `.agents/skills/testing/SKILL.md`, docs for QA/castor guidance.

## Acceptance criteria
- `castor check` no longer kills active Hatfield control-plane workers when invoked from within the same checkout/session.
- Stale-worker cleanup protects launcher ancestry plus same-session siblings or otherwise scopes kills only to check/test-owned stale workers.
- Docs and testing/task workflow guidance explain safe full-check execution from active Hatfield sessions, including worktree guidance if still recommended.
- Regression proof exists for cleanup selection logic without killing real processes, plus focused Castor validation; full `castor check` is runnable after the fix.
