# SUBAGENT-LIVE-03 Child HITL, attention, and cancellation

## Goal
Build on SUBAGENT-LIVE-01/02 to productionize child HITL and child cancellation. Reference POC: `/home/ineersa/projects/agent-core-worktrees/subagent-live-view-steering-poc`, latest known POC head `b5c6fca29`; planning doc `.aiassistant/fork/subagent-live-view-production-plan.md`.

POC evidence/lessons:
- Child `ask_human` and SafeGuard HITL can be surfaced through live view and answered back to child run id.
- Existing subagent system had an 8-layer noninteractive enforcement chain: session.interactive=false, WaitingHuman treated as failure, NoninteractiveChildRunProbe, extension approval auto-deny, SafeGuard auto-deny, child prompt says not to ask humans, tool descriptions, and allowlist behavior.
- Production must intentionally define foreground subagents as interactive-capable instead of accidental bypass.
- Main screen needs clear attention when child waits for human input.
- Question ownership must be run-scoped; parent and child questions must not close/answer each other.
- ESC in live view should not accidentally cancel parent; question overlay should own ESC/Enter before child cancel/steer.

Scope:
- Define interactive foreground subagent contract.
- Allow child `ask_human` and SafeGuard approvals through parent TUI/live view where appropriate.
- Bridge child HITL runtime events into QuestionCoordinator/QuestionController with explicit child run ownership and child labels.
- Answer callbacks target child run id.
- Main screen attention indicator when any child needs input; picker rows sort/mark waiting children.
- Child cancel behavior from live view via ESC and/or `/agents-cancel`.
- Parent cancel behavior remains unchanged in main mode.
- Orphaned question rejection must be scoped by run id/source.

Architecture guidance:
- Consider adding run id/source fields to question requests if not already sufficient.
- Single question queue is risky; avoid parent/child question confusion.
- Do not log raw prompts/tool output in HITL/cancel logs.
- Keep headless/noninteractive subagent mode as future explicit design if needed; do not add broad compatibility shims.

## Acceptance criteria
- A child subagent can call `ask_human`; the TUI shows a clearly labelled child question and answer is delivered to child run id.
- A child subagent can trigger SafeGuard approval; approval/rejection is delivered to child run id.
- Main screen shows visible child-needs-input status without requiring user to already be in live view.
- `/agents-live` picker clearly marks/sorts children needing input.
- Question overlay input takes precedence over child steering/cancel; child cancel does not fire underneath an active question overlay.
- ESC or `/agents-cancel` in child live view cancels selected child run, not parent run.
- Parent HITL and child HITL ownership do not collide; terminal child does not reject unrelated parent question.
- Automated proof covers child HITL answer routing and child cancel target; focused Castor validation recorded.
