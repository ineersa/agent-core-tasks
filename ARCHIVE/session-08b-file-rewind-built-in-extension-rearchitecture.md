# Rearchitect file rewind as opt-in built-in extension

## Goal
Follow-up to abandoned SESSION-08 prototype / closed PR #249.

Reference branch kept intentionally: `origin/task/session-08-exact-file-rewind-checkpoints` through commit `50e038805`.

What worked in the prototype:
- Hatfield-owned hidden-git backend can capture/restore files without mutating the user's project `.git`.
- Restore to a prior checkpoint worked in manual smoke.
- Undo-last-file-rewind partially worked and the hidden-git/undo model is promising.
- Safety/proof work around project `.git` untouched, `.hatfield/rewind` ignored, per-commit refs, and git subprocess isolation is useful reference material.

Why PR #249 was closed without merge:
- The implementation was too intrusive for a non-core feature: it touched runtime protocol, TUI tree navigation, run locks, worker failure recovery, session events, settings, deptrac, hidden git, and many tests.
- Manual smoke still found serious regressions: duplicated turns in `/tree` (e.g. repeated Turn 2/3 and Turn 5/6 prompts) and session 3 stuck in `◐ Working...`.
- The feature crossed critical liveness boundaries; normal chat must remain more important than file rewind.

New direction:
Design file rewind as an opt-in built-in extension, disabled by default or explicitly enableable, with minimal core/runtime footprint. The extension should provide file checkpoint/restore capability without coupling destructive filesystem restore into the default `/tree` navigation path until proven stable.

## Acceptance criteria
- Design document compares prototype branch decisions against the new extension architecture and explicitly lists code to reuse vs discard.
- File rewind can be disabled completely; when disabled, normal chat, run locks, `/tree`, replay, and TUI runtime behavior are unaffected.
- No hidden-git checkpoint capture or restore work runs inside the agent run lock / command mailbox critical path.
- Core AgentCore remains independent of CodingAgent/TUI/extension implementation; any new integration uses existing extension hooks or a minimal general-purpose extension seam.
- Initial implementation exposes file restore through explicit extension-owned UX/command flow, not automatic destructive `/tree` navigation.
- Live smoke proof covers: start session, assistant response, immediate follow-up without stuck Working, file-changing tool, restore, undo, and normal `/tree` without duplicated turns.
- Safety invariants retained from prototype: user's project `.git` index/objects/refs/staging/config are untouched; `.hatfield/rewind` is ignored; restore has undo metadata; partial restore failures surface visibly.
- PR includes a smaller blast radius than #249 and documents remaining limitations such as secrets in snapshots, transactional restore boundaries, retention/GC, and large-file behavior.
